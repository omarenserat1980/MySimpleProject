# Brain ASIC — Single-Unit Build Contract

**Decision:** Build exactly one Brain ASIC design instance for the documented Brain workload. Treat this as one canonical RTL/hardware product, not a fleet of invented devices.
**Owner:** User
**Product / manufacturer label:** Brain (project-defined)
**Budget:** 0 JOD; use existing repository tooling and free CI only. No purchases, paid provisioning, foundry orders, production changes, or secret changes are authorized by this document.
**Evidence rule:** Never report simulated/synthesized results as physical silicon, live mining, hashrate, revenue, or profit.

## 1. What “one ASIC” means in this project

The initial deliverable is one canonical, versioned digital hardware design instance and its complete reproducible toolchain. The repository currently contains RTL prototypes and simulation/synthesis infrastructure; these artifacts do **not** establish that a physical chip has been fabricated.

A physical custom ASIC requires a process-specific design, timing/power/area signoff, foundry acceptance, fabrication/package traceability, and independent lab evidence. That is a later gate and is not implied by this plan.

## 2. Workload contract

The single design must be traceable to the documented workload rather than claiming to execute every arbitrary Brain software program directly in silicon.

Initial hardware acceleration target:
- Bitcoin proof-of-work SHA-256d datapath and bounded nonce-search interface where supported by the existing RTL.
- Deterministic control/status interface so Brain software can submit jobs and collect results.
- Shared golden test vectors and independent software-reference comparisons.
- Existing general-purpose ALU RTL remains a separately tested block until integration is demonstrated.

The Brain software remains responsible for orchestration, memory, network protocols, pool authentication, job scheduling, policy, evidence collection, and financial gates. The ASIC datapath must not receive pool credentials or be allowed to authorize financial actions.

## 3. Canonical source and evidence

Canonical RTL starts from the existing files, including:
- `brain_v12/asic/rtl/brain_asic_core.sv`
- SHA-256 / SHA-256d and bounded-nonce RTL/testbenches under `brain_v12/asic/rtl/`
- `brain_v12/asic/digital_lab.py`
- `brain_v12/asic/execute_asic_pipeline.py`
- `brain_v12/asic/toolchain_probe.py`
- `.github/workflows/brain-digital-asic-lab.yml`
- `.github/workflows/asic-rtl-to-gds.yml`

Before extending or integrating RTL, inspect the actual current sources and preserve existing acceptance tests. Do not silently replace a specialized SHA-256d mining design with the generic ALU block.

Every run should preserve, at minimum:
- exact commit SHA and RTL source hashes;
- tool names and versions;
- simulator command, exit code, and required PASS marker;
- synthesis exit code, checked netlist, warnings/errors and statistics;
- golden-vector results and nonce/endianness boundary cases;
- explicit missing-tool and incomplete-gate statuses;
- timestamps generated by the running system, not hard-coded.

## 4. Ordered acceptance gates

1. **Inventory:** map every documented workload to its owning RTL module, software adapter, testbench, tool, and missing dependency.
2. **Reproducible RTL:** real Icarus Verilog or Verilator execution with non-vacuous test vectors; Python-only tests do not satisfy this gate.
3. **Correctness:** differential comparison against an independent SHA-256d software reference, including byte order, target comparison, nonce boundaries, reset, and backpressure where applicable.
4. **Synthesis:** Yosys or another real synthesis tool must emit a checked, non-empty netlist with source hashes and reports.
5. **Physical design experiment:** resolve the existing OpenROAD/SDC configuration and run the available open PDK flow if its dependencies are available; report constraints and limitations. A GDSII file alone is not proof of fabrication.
6. **Hardware interface:** define register map, reset/clock contract, input/output protocol, error reporting, and a deterministic software adapter.
7. **Physical prototype:** only if suitable hardware already exists at zero cost; verify device identity and measured I/O independently. Do not imply FPGA or silicon exists without evidence.
8. **Mining integration:** prove pool-issued work, locally computed candidate, accepted share response, and worker-side telemetry separately. A pool hashrate display alone does not prove this Brain design generated the work.
9. **Financial gate:** payouts must be evidenced separately; net profit requires measured power draw and the actual electricity tariff. Keep financial execution disabled until explicitly authorized and all gates pass.

## 5. Gaps are backlog, not blockers to documenting the design

Track each missing dependency or capability with an owner, exact file/tool, reproducible failure evidence, and a testable exit criterion. Brain may propose and implement software changes in isolated branches, but must not fabricate evidence, bypass failed gates, change production settings, create credentials, or incur costs.

Known areas to investigate from the existing repository baseline:
- confirm the mining SHA-256d RTL and bounded-nonce flow are wired into the canonical lab;
- ensure RTL tests are actually executed (not skipped) and include independent golden vectors;
- fix and validate the existing OpenROAD `constraint.sdc` path/configuration issue;
- produce one machine-readable evidence manifest for simulation, synthesis, PPA, hardware, pool activity, payout, and net profit, each with independent status;
- ensure missing EDA tools are reported as BLOCKED, not PASS.

## 6. Non-negotiable status vocabulary

- `RTL_SIMULATION_PASS`: testbench passed on a real RTL simulator.
- `SYNTHESIS_PASS`: synthesis completed and checked netlist/reports exist.
- `PHYSICAL_DESIGN_PASS`: a documented physical-design flow completed under stated constraints; not fabrication proof.
- `PHYSICAL_DEVICE_VERIFIED`: a physical device has identity and independent measurements.
- `LIVE_MINING_VERIFIED`: evidence links the exact design/device to real work and accepted shares.
- `PAYOUT_VERIFIED`: independently supported payout evidence exists.
- `NET_PROFIT_VERIFIED`: payout/revenue, measured power, and actual costs support a positive net result.
- `BLOCKED` / `FAIL`: required evidence is missing or a check failed.

No gate automatically advances another gate. Do not assign a fabricated hashrate, temperature, power draw, payout, or profit to the Brain ASIC.

## 7. Definition of done for this first build contract

- One canonical design instance is named and versioned.
- Every documented target workload maps to RTL/software/test/tool entries or an explicit gap.
- Real RTL simulation and synthesis have independent evidence artifacts.
- Gaps are recorded with reproducible exit criteria.
- No claim of physical manufacture, live mining, or realized income is made without corresponding evidence.
