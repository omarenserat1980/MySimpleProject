# برومبتات ChatGPT لتطوير Electronic Brain على محاكي Cloudflare

هذه البرومبتات مخصصة للمستودع `omarenserat1980/MySimpleProject` ومسار `cloudflare/brain-api`. استخدمها مع سجلات التشغيل أو الملفات الفعلية، ولا تضع مفاتيح أو رموز وصول داخل المحادثة.

## 1) تشخيص فشل بوابة المحاكي

> افحص ملفات `cloudflare/brain-api` وسجل GitHub Actions المرفق. حدّد السبب الجذري لكل فشل مع الإشارة إلى الملف والسطر أو خطوة CI. افصل بين فشل المحاكي وفشل النشر الحقيقي. اقترح أصغر إصلاح آمن، أضف اختبارًا يعيد إنتاج المشكلة، ولا تغيّر الأسرار أو إعدادات الحساب ولا تنفذ النشر الحقيقي. لا تدّع نجاحًا دون نتيجة اختبار واضحة.

## 2) بناء مسار محلي قابل للتكرار

> طوّر مسارًا محليًا لمحاكي Cloudflare Worker باستخدام Wrangler وD1 المحلي، واستخدم بيانات اختبار اصطناعية فقط. راجع `wrangler.toml` قبل التعديل. لا تتصل بحساب Cloudflare ولا تنفّذ ترحيلات عن بُعد. أضف أو حدّث الاختبارات ووثّق أوامر التشغيل والتنظيف، مع توضيح حدود المحاكاة مقارنة بالإنتاج.

## 3) إضافة Endpoint جديد

> أضف endpoint باسم [المسار] إلى Worker الموجود، مع احترام البنية الحالية وعدم إنشاء بوابة API أو مزوّد AI أو مسارات مكررة. حدّد عقد الطلب والاستجابة، والتحقق من المدخلات، وCORS والمصادقة المناسبة، والأخطاء المتوقعة. أضف اختبارات نجاح وفشل وحدود ومدخلات غير صالحة. حافظ على توافق الواجهات القديمة ولا تستخدم بيانات أو أسرار حقيقية.

## 4) اختبار D1 وR2 بأمان

> صمّم اختبارات معزولة لتكامل D1 وR2 باستخدام قواعد بيانات وملفات اختبار محلية أو محاكاة مناسبة. غطّ التكرار، وإعادة المحاولة، والبيانات الناقصة، وفشل التخزين، وعدم تطابق المبلغ والعملة عند اختبار الدفع. لا تنفّذ دفعًا حقيقيًا ولا تنشئ أو تحذف موارد سحابية ولا تفعّل R2. إذا كانت ميزة غير مدعومة محليًا، اذكرها بوضوح ولا تستبدلها بنتيجة نجاح وهمية.

## 5) مراجعة الأمان قبل الدمج

> راجع التغيير المقترح بحثًا عن تسريب الأسرار، وغياب المصادقة، وCORS غير الآمن، وحقن SQL، وإعادة تشغيل إشعار الدفع، والتلاعب بالمبلغ أو العملة، وسجلات تحتوي بيانات حساسة. صنّف النتائج حسب الخطورة، وقدّم اختبارات تثبت كل نتيجة. لا تطبع قيم الأسرار ولا تطلب مني إرسالها. لا تعتمد التغيير أو تدمجه تلقائيًا.

## 6) إصلاح CI وإثبات النتيجة

> افحص آخر تشغيل GitHub Actions المرتبط بالالتزام [SHA أو رابط التشغيل]. استخرج الخطوات الفاشلة فقط، ثم اربط كل إخفاق بسبب جذري وتغيير واختبار. شغّل بوابة المحاكي دون أسرار Cloudflare، واحفظ ملخص الأدلة مع معرّف التشغيل والالتزام. ميّز بوضوح بين PASS للمحاكي ونجاح النشر الحقيقي. لا تقل إن Worker أو Windows VM يعمل ما لم يوجد فحص حي مستقل يثبت ذلك.

## 7) اقتراحات ChatGPT لإصلاح الأعطال (استشارية فقط)

> حلّل سجل الخطأ التالي: [ألصق سجلًا منقحًا من الأسرار]. أعطني: (1) ملخص المشكلة، (2) الأسباب المحتملة مرتبة حسب الدليل، (3) أقل إصلاح ممكن، (4) اختبارات قبل وبعد، (5) المخاطر والتراجع، (6) مستوى الثقة وما ينقص من الأدلة. افصل الحقائق عن الفرضيات. لا تنفّذ أوامر مدمرة ولا تنشر إلى السحابة ولا تغيّر حالة الدفع.

## أوامر DevKit

من جذر المستودع:

```bash
bash cloudflare/brain-api/scripts/brain-cloudflare-devkit.sh status
bash cloudflare/brain-api/scripts/brain-cloudflare-devkit.sh doctor
bash cloudflare/brain-api/scripts/brain-cloudflare-devkit.sh test
bash cloudflare/brain-api/scripts/brain-cloudflare-devkit.sh dev
bash cloudflare/brain-api/scripts/brain-cloudflare-devkit.sh prompts
```

- الوضع الافتراضي `emulator` ولا يحتاج أسرار Cloudflare.
- الأمر `dev` يشغّل Wrangler محليًا؛ قد يتطلب تنزيل حزمة Wrangler أول مرة.
- `test` لا يثبت أن النشر الحقيقي يعمل.
- `deploy` محجوب ما لم تُفعّل وضعية النشر الحقيقي صراحةً، ويظل نشر الإنتاج خارج مسار التطوير الاعتيادي.
- لا تضع `CLOUDFLARE_API_TOKEN` أو مفاتيح PayTabs أو أي أسرار في البرومبتات أو السجلات.
