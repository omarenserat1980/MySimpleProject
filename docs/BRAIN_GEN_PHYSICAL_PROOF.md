# Brain GEN — Physical Evidence Gate

## Purpose

GEN is a software evidence workflow inside Electronic Brain V12. It must distinguish verified evidence about a physical device from simulator output, caller-supplied claims, and unverified telemetry. GEN does not create physical hardware, and software-only tests are never evidence that a physical ASIC exists.

## Safety and truth invariants

- Default state is `NOT_PROVEN`; missing, stale, contradictory, or unverifiable evidence fails closed.
- `SIMULATED`, `CLAIMED`, `CONNECTED_UNVERIFIED`, and `PHYSICALLY_ATTESTED` are distinct states. Only the final state can satisfy a physical-device proof gate.
- Never label a simulator, CI runner, cloud web service, or registry entry as a physical ASIC.
- Do not enable external network access, provision paid resources, change production configuration, deploy, start mining, or handle wallet secrets automatically.
- Do not store tokens, passwords, private keys, seed phrases, or raw credentials in evidence records or logs.
- A hash of caller-supplied JSON proves integrity of that JSON after recording, not the truth of the claims inside it.
- Provider claims and public dashboards alone do not prove that a named device answered a live challenge.

## Evidence workflow

1. **DISCOVER** — enumerate only explicitly configured sources; do not scan arbitrary networks.
2. **IDENTIFY** — record provider/device identity and the provenance of the identity assertion.
3. **AUTHORIZE** — require an explicit allowlisted endpoint and permitted diagnostic operations before any external connection.
4. **CHALLENGE** — generate a fresh unpredictable nonce; bind the response to the nonce, device identity, requested operation, and time window.
5. **VERIFY** — validate the response signature against a previously trusted key or independently verified provider attestation. TLS alone proves a protected connection to an endpoint, not that the endpoint is the claimed ASIC.
6. **TEST** — issue a read-only diagnostic supported by the real device interface and verify the returned device-side result. A simulator result is always tagged `SIMULATED`.
7. **RECORD** — store a versioned evidence record with UTC timestamps, source, device/provider identity, challenge ID, operation, response digest, verifier outcome, and limitations.
8. **RECHECK** — expire stale evidence and require a new challenge for each proof session.
9. **REPORT** — emit `PHYSICALLY_ATTESTED` only when all required independent checks pass; otherwise report the exact blocked reason.

## Evidence record (schema contract)

Required fields:

- `schema_version`
- `evidence_id`
- `subject_type` (`ASIC_DEVICE` or `HOSTED_ASIC`)
- `subject_id`
- `source_type` (`SIMULATOR`, `CALLER_CLAIM`, `PROVIDER_API`, or `DEVICE_ATTESTATION`)
- `observed_at_utc` and `expires_at_utc`
- `challenge_nonce_digest` (never log the secret nonce if policy forbids it)
- `operation` and `result_digest`
- `identity_verification` and `signature_verification`
- `network_connection_verified`
- `physical_presence_verified`
- `status` and machine-readable `blocked_reasons`
- `verifier_version`

Every boolean must include a source and method in the full record. Unknown is not false evidence and must not be coerced to true.

## Status rules

- `NOT_PROVEN`: default, no sufficient evidence.
- `SIMULATED`: generated by a software model; never proves hardware.
- `CLAIMED`: caller or provider supplied a claim not independently verified.
- `CONNECTED_UNVERIFIED`: a live endpoint answered, but identity/device binding is not proven.
- `CHALLENGE_FAILED`: nonce, freshness, signature, or response binding failed.
- `PHYSICALLY_ATTESTED`: fresh challenge succeeded; identity is independently trusted; the response is cryptographically bound to the subject and challenge; a real-device diagnostic passed; and evidence provenance is recorded.
- `EXPIRED`: evidence exceeded its validity window.

A reachable IP address, open port, successful HTTP status, CI pass, simulated hashrate, or locally computed evidence hash is insufficient for `PHYSICALLY_ATTESTED`.

## ASIC-specific proof limits

A device diagnostic can establish connectivity and reported device state, but not profitable mining or revenue. Real mining requires separately authorized pool connectivity and verified work submission. Revenue is proven only by an independently verifiable payout reaching the user's own wallet; never request wallet seed phrases or private keys.

## Zero-budget behavior

GEN may inspect public documentation and validate an offer offline. It must not enroll, activate, pay, provision, or connect to a provider automatically. Missing trial terms, unclear physical-device disclosure, fees, withdrawal restrictions, or missing independent identity evidence must block activation.

## Acceptance tests

1. Simulator output always returns `SIMULATED`, never `PHYSICALLY_ATTESTED`.
2. Caller-supplied telemetry with a valid digest but no independent identity remains `CLAIMED`.
3. A live endpoint with no trusted device binding remains `CONNECTED_UNVERIFIED`.
4. Replayed nonce, stale response, invalid signature, or mismatched subject fails closed.
5. Missing evidence returns `NOT_PROVEN` with explicit blocked reasons.
6. Expired evidence returns `EXPIRED`.
7. Only a fresh, cryptographically bound challenge and a passing real-device diagnostic can reach `PHYSICALLY_ATTESTED`.
8. Unit tests require no external network, secrets, paid services, production changes, or real mining.
9. Reports clearly separate physical-device proof from mining-work proof and payout proof.

## Implementation sequence

1. Implement a pure, offline evidence schema validator and status evaluator.
2. Add deterministic unit tests for all fail-closed cases.
3. Integrate the evaluator with the existing ASIC resource adapter without changing its simulator semantics.
4. Add a separately disabled connector interface for an explicitly configured provider/device; require review and authorization before any live call.
5. Only after a real device/provider and trusted identity mechanism are available, perform a bounded live challenge and retain redacted evidence.
