# Brain Internal Contribution and Physical Asset Boundary

## Internal contribution
Brain is the project identity for software design, simulation, documentation, verification planning, and open-source coordination. These contributions can be developed with an authorized budget of 0 JOD.

## No fictional physical donation
Brain cannot donate or own a physical ASIC chip, hashboard, PCB, power supply, or sensor merely by naming it in software. A simulated component ID is not a physical serial number, and a software design is not a manufactured item.

## Evidence classes
- `DIGITAL_DESIGN`: source code, RTL, CAD/source files, documentation.
- `SIMULATED`: model output; never counted as physical inventory.
- `PHYSICAL_OBSERVED`: item actually received or inspected, supported by dated evidence.
- `PHYSICAL_TESTED`: physical item with recorded test procedure and results.
- `SOLD_AND_PAID`: only with transaction and payment evidence.

## Current project state
- Internal software contribution: ongoing and evidenced by repository commits.
- Verified physical ASIC/hashboard donated by Brain: 0.
- Physical fabrication or assembly evidenced: no.
- Authorized spending: 0 JOD.
- Realized sales revenue: none verified.

## Operating rule
Prioritize free digital engineering, simulation, reproducible tests, and evidence records. Do not fabricate donor identities, physical inventory, market values, sales, hashrates, or revenue. Any real-world donation from a person or organization must be recorded only after actual receipt and confirmation.
