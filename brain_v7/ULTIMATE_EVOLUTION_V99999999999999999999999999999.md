## Non-negotiable completion rule

A milestone is COMPLETE only when:
1. its code exists;
2. its interface is documented;
3. its behavior is observable;
4. its change is recorded;
5. its permissions are explicit;
6. failure/recovery behavior is defined;
7. the previous stable state can be restored.

The system must never claim a capability merely because a version number was advanced.

## Independence model

The brain can independently generate goals, plans, research tasks and tool requests. External execution remains bounded by registered tools, explicit permissions, resource limits, audit logs, and an emergency stop. This prevents a version milestone from silently becoming unrestricted control of a host device.

## Ultimate target

V99999999999999999999999999999 is treated as a long-range architectural horizon for one continuously evolving system, not billions of fabricated commits or releases.
